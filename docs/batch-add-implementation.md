# 批量新增权限增强实施方案

## 需求与实现边界

以现有代码为依据，保持新增权限的 SQL 预览、确认执行与结果弹窗流程，不新增测试代码。

1. 执行成功后保留目标范围、权限与数据范围及批量列选择，避免重复配置；人员输入可在全部成功后清除，失败时保留用于修正。
2. 批量输入增加可勾选列：权限（显示名）、数据范围（显示名）、项目、环境、数据库、权限表。未勾选属性沿用下方统一配置；勾选属性以每行单个显示名为准，不接受数据库枚举值作为替代。
3. 行格式按固定列顺序展示并随勾选动态变化，工号必填、姓名允许空值，已勾选属性每行必填；缺列、多列、名称未知或歧义、无匹配目标应给出行号错误并阻止预览，避免误授权。
4. 同一工号不同属性组合应保留，完全重复的授权输入去重。逐行解析并汇总预览，后端复用现有授权生成路径；不执行真实业务库写入作为验证。

## 并行分工

- 前端：输入列勾选、动态格式与示例、校验提示、按行请求契约、保留成功执行后的设置。
- 后端：核查并扩展预览请求以支持按行目标/权限/范围名称解析，保持旧请求兼容。
- 发布核查：只读检查打包脚本、版本与现有 Release，再安排构建验证与正式发布。

## 已实现用法与契约

- 勾选批量属性后，行格式为 `工号,姓名,已勾选属性…`；属性按权限、数据范围、项目、环境、数据库、权限表的固定顺序排列。姓名为空时保留分隔符，如仅勾选权限时 `u001,,查看报表`。
- 未勾选批量属性时继续支持 `工号` 或 `工号,姓名`。中英文逗号均可；不支持含逗号的名称转义。
- 勾选的属性由每行提供，对应全局控件禁用但原选择保留，不参与本次过滤；批量模式不自动修剪既有全局选择。取消勾选后可继续复用。
- 新增预览请求支持 `rows`，每行包含 `id`、可空 `name` 和可选 `permissionLabel`、`scopeLabel`、`projectName`、`environmentName`、`databaseName`、`tableTitle`。字段缺省沿用全局，出现则必须为非空显示名称（姓名例外）；旧 `persons` 契约兼容。
- 后端先校验全部行，名称未知、上下文无法消歧或无匹配目标时报行号，避免静默扩大授权。按目标表及工号×范围×权限去重，前端使用结构化键防止字符串拼接碰撞。
- 执行全部成功后仅清除人员文本，保留目标、权限、范围与列勾选；失败保留输入。批量摘要以实际 SQL 预览为准。
